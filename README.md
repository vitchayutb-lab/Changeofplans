# 🏦 SME Finance Copilot — ผู้ช่วยการเงิน SME

เว็บแอปที่ปรึกษาการเงินสำหรับ SME ไทย: อ่านงบการเงินของกิจการ ดึงข้อมูลดอกเบี้ยและอัตรา
แลกเปลี่ยนจริงจาก **Bank of Thailand API** แล้วตอบคำถามเรื่องการกู้เงินและแหล่งเงินทุน
โดยที่ **ตัวเลขทุกตัวในคำตอบต้องมาจากการเรียกเครื่องมือจริง** และตรวจย้อนกลับได้

> ℹ️ ที่เก็บโค้ดนี้มีสองแอป: **SME Finance Copilot** (TypeScript, อยู่ใน `apps/` และ `packages/`)
> ซึ่งเป็นแอปหลักที่เอกสารนี้อธิบาย และ **MemeCoin Auto-Bot** เดิม (Python/Streamlit,
> อยู่ที่ราก) ที่ยังคงไว้ตามเดิม — ดูหัวข้อท้ายไฟล์

## เริ่มใช้งานใน 3 คำสั่ง

```bash
npm install
npm run build          # สร้าง shared types → server → web
npm start              # เปิด http://localhost:8787
```

ระหว่างพัฒนา (แยกสองหน้าต่าง):

```bash
npm run dev:server     # API ที่ http://localhost:8787
npm run dev:web        # หน้าเว็บที่ http://localhost:5173 (proxy /api ไปที่ 8787)
```

**ไม่ต้องตั้งค่าอะไรเลยก็รันได้ทันที** ระบบจะเข้าสู่ DEMO MODE และติดป้าย `Demo Data`
ให้ทุกตัวเลขที่มาจากข้อมูลจำลอง

## นำขึ้นเว็บจริง (ไม่ใช่ localhost)

แอปนี้ต้องรันบนเซิร์ฟเวอร์ Node จริง **ใช้ static hosting ไม่ได้** เพราะ `BOT_API_KEY`
ต้องอยู่ฝั่งเซิร์ฟเวอร์เท่านั้น (กฎ R3) ที่เก็บโค้ดจึงมีไฟล์ deploy พร้อมใช้:

| ไฟล์ | ใช้กับ |
|---|---|
| [`Dockerfile`](Dockerfile) | ทุกที่ที่รับ Docker — Render, Railway, Fly.io, Cloud Run, VPS |
| [`render.yaml`](render.yaml) | Render Blueprint (มีแผนฟรี กดสองครั้งจบ) |
| [`fly.toml`](fly.toml) | Fly.io พร้อมดิสก์ถาวรสำหรับ SQLite |

**วิธีที่เร็วที่สุด — Render:** เข้า [dashboard.render.com](https://dashboard.render.com)
→ **New** → **Blueprint** → เลือก repo นี้ → **Apply** จบแล้วได้ URL สาธารณะ
แอปจะขึ้นใน DEMO MODE ทันที จากนั้นค่อยใส่ `BOT_API_KEY` ในหน้า Environment
เพื่อสลับไปใช้ข้อมูลจริงจาก ธปท.

**Docker ที่ไหนก็ได้:**

```bash
docker build -t sme-finance-copilot .
docker run -d -p 80:8787 -e BOT_API_KEY=xxxxx -v sme-data:/data sme-finance-copilot
```

ขั้นตอนเต็มของแต่ละแพลตฟอร์ม ตัวแปรที่ต้องตั้ง และเช็กลิสต์หลัง deploy อยู่ที่
[`docs/06-deployment.md`](docs/06-deployment.md)

## 🏦 การเชื่อมต่อ Bank of Thailand API

### BOT API คือแหล่งข้อมูลการเงินภายนอกหลักของระบบนี้

ทุกตัวเลขที่เกี่ยวกับ "ราคาของเงิน" — ดอกเบี้ยนโยบาย ดอกเบี้ยเงินกู้ ดอกเบี้ยเงินฝาก
อัตราแลกเปลี่ยน อัตราตลาดเงิน — มาจาก ธปท. ไม่มีค่าคงที่ฝังในโค้ด แม้แต่การคิดดอกเบี้ยของ
สินเชื่อเดิมที่เป็นอัตราลอยตัว ระบบก็คิดใหม่จากอัตราอ้างอิงล่าสุดทุกครั้งที่เรียกดู

### สถาปัตยกรรม: เบราว์เซอร์ไม่เคยคุยกับ BOT โดยตรง

```
   เบราว์เซอร์ (React)
        │  fetch /api/bot/*        ← ไม่มี API key ไม่รู้จัก host ของ BOT
        ▼
   Backend API (Express)
        │
        ▼
   BOT API Adapter  ── botService (แคช + ทางถอย)
        │            └─ botClient  (ที่เดียวที่ถือ BOT_API_KEY)
        ▼
   Bank of Thailand API  (gateway.api.bot.or.th)
```

### การตั้งค่า API key

คัดลอก `.env.example` เป็น `.env` ที่รากโปรเจกต์ แล้วใส่ค่า:

```bash
# วางคีย์ล้วน ๆ ห้ามมีวงเล็บ < > หรือเครื่องหมายคำพูดครอบ
BOT_API_KEY=eyJvcmciOiJ...
```

ตัวแปรที่เหลือมีค่าเริ่มต้นที่ใช้ได้อยู่แล้ว ตั้งเพิ่มเมื่อต้องการเปลี่ยนเท่านั้น:

```bash
BOT_API_BASE_URL=https://gateway.api.bot.or.th
BOT_API_KEY_HEADER=Authorization
BOT_TIMEOUT_MS=8000
BOT_MAX_RETRIES=2
BOT_MAX_RPS=5
```

> คีย์เดียวไม่ได้เปิดทุกชุดข้อมูล — ต้อง **Subscribe** แต่ละชุดในหน้า Catalogues ของพอร์ทัลก่อน
> ถ้ายังไม่ได้ subscribe เกตเวย์จะตอบ `403 Access to this API has been disallowed`
> (คนละอาการกับคีย์ผิดซึ่งได้ `401`) ระบบยกข้อความจริงจาก ธปท. มาแสดงให้เห็นทั้งสองกรณี

> ⚠️ **`BOT_API_BASE_URL` ใส่เฉพาะโฮสต์ ห้ามใส่ path ของ endpoint ต่อท้าย** — path ของ
> แต่ละชุดข้อมูลอยู่ใน `botSeries.ts` แล้ว ธปท. ปิดเกตเวย์เดิม `apigw1.bot.or.th` ไปเมื่อ
> 31 ธ.ค. 2025 และย้ายมาที่ `gateway.api.bot.or.th` (คนละตัวกับ `portal.api.bot.or.th`
> ซึ่งเป็นเว็บไซต์สำหรับสมัครและอ่านเอกสาร) ระบบตรวจทั้งสามกรณีที่ตั้งผิดบ่อยและบอกวิธีแก้
> รายละเอียดอยู่ที่ [`docs/06-deployment.md` §6.9](docs/06-deployment.md)

ข้อกำหนดด้านความปลอดภัยที่ระบบบังคับไว้:

- `BOT_API_KEY` ถูกอ่านที่ [`apps/server/src/config/env.ts`](apps/server/src/config/env.ts) **ที่เดียว**
  และถูกใช้ที่ [`botClient.ts`](apps/server/src/services/bot/botClient.ts) ที่เดียว
- ไม่มีตัวแปรขึ้นต้นด้วย `VITE_` ที่ถือความลับ (Vite จะฝังค่าพวกนั้นลงไฟล์ที่เบราว์เซอร์โหลด)
- `.env` อยู่ใน `.gitignore` แล้ว — commit ได้เฉพาะ `.env.example` ที่ค่าว่าง
- ข้อความ error ทุกอันถูกกรองผ่าน `redactSecrets()` ก่อนบันทึก log หรือส่งกลับ
- `GET /api/health` บอกแค่ `apiKeyConfigured: true/false` ไม่เคยบอกค่าหรือความยาวของคีย์
- มีเทสต์ที่ตั้งคีย์ปลอมแล้วยิงทุก endpoint เพื่อยืนยันว่าไม่มี response ไหนมีคีย์ติดออกมา
  (`apps/server/tests/api.test.ts` → "ความปลอดภัยของ API key")

### ข้อมูล BOT ที่ระบบใช้

ทะเบียนอยู่ที่ [`botSeries.ts`](apps/server/src/services/bot/botSeries.ts) — เพิ่มชุดใหม่ =
เพิ่มรายการเดียว ไม่ต้องแก้ route ไม่ต้องแก้ client

| รหัสชุดข้อมูล | ข้อมูล | path บน BOT API | อายุแคช | ตรวจกับของจริง |
|---|---|---|---|---|
| `policy_rate` | อัตราดอกเบี้ยนโยบาย | `/PolicyRate/v3/policy_rate` | 60 นาที | ✅ |
| `lending_rate` | ดอกเบี้ยเงินกู้ MLR / MOR / MRR | `/LoanRate/v2/loan_rate/` | 60 นาที | ✅ |
| `deposit_rate` | ดอกเบี้ยเงินฝาก ออมทรัพย์ / 3M / 6M / 12M / 24M | `/DepositRate/v2/deposit_rate/` | 60 นาที | ✅ |
| `spot_rate` | อัตราแลกเปลี่ยนทันที USD/THB | `/Stat-SpotRate/v2/SPOTRATE/` | 10 นาที | ✅ |
| `interbank_rate` | ดอกเบี้ยระหว่างธนาคาร | `/Stat-InterbankTransactionRate/v2/INTRBNK_TXN_RATE/` | 30 นาที | — |
| `bibor` | BIBOR 1M / 3M / 6M | `/BIBOR/v2/bibor/` | 30 นาที | — |
| `thb_implied_rate` | ดอกเบี้ยเงินบาทโดยนัย | `/Stat-ThaiBahtImpliedInterestRate/v2/THB_IMPL_INT_RATE/` | 6 ชั่วโมง | — |
| `external_rate` | ดอกเบี้ยต่างประเทศ | `/Stat-ExternalInterestRate/v2/EXT_INT_RATE/` | 6 ชั่วโมง | — |
| `fx_reference` | อัตราอ้างอิง THB/USD | `/Stat-ReferenceRate/v2/DAILY_REF_RATE/` | 10 นาที | ❌ คนละ product |
| `fx_average` | อัตราแลกเปลี่ยนเฉลี่ย 6 สกุล | `/Stat-ExchangeRate/v2/DAILY_AVG_EXG_RATE/` | 10 นาที | ❌ คนละ product |

ธปท. ให้สิทธิ์เป็น **product** ไม่ใช่รายชุด สี่ชุดที่ยังไม่มีเครื่องหมายอยู่ในแพ็ก
*Interest Rates Plan* เดียวกับชุดที่ผ่านแล้ว แค่ยังไม่มีหน้าไหนเรียก ส่วนสองชุดสุดท้าย
อยู่ในแพ็กอัตราแลกเปลี่ยนซึ่งต้อง subscribe แยก

> **หมายเหตุเรื่องชื่อคอลัมน์** แต่ละ endpoint ของ BOT ตั้งชื่อฟิลด์ไม่เหมือนกันและปรับได้ตาม
> เวอร์ชัน ระบบจึงเก็บ "รายชื่อคอลัมน์ที่เป็นไปได้" ไว้ในทะเบียน แล้วเลือกอันแรกที่เจอ
> ยกเว้นชุดที่ตั้ง `averageValueFields` ไว้ ซึ่งจะอ่านทุกคอลัมน์ที่ตรงแล้วเฉลี่ยรวมกัน
> ใช้กับค่าที่ ธปท. ประกาศเป็นคู่ เช่น เงินฝากที่ให้ `_min`/`_max` และอัตราแลกเปลี่ยนที่ให้
> `bid_rate`/`offer_rate` — ค่าที่ได้จึงเป็นจุดกึ่งกลาง ไม่ใช่ขอบใดขอบหนึ่ง
> ถ้าไม่เจอคอลัมน์ที่อ่านได้เลยจะถือว่ารูปแบบไม่ตรงและ**ถอยไปใช้ข้อมูลสำรองพร้อมแจ้งเตือน
> แทนที่จะเดาค่า** ปรับ mapping ได้ที่ `valueFields` ในทะเบียนโดยไม่ต้องแตะโค้ดส่วนอื่น

### สิ่งที่รู้จากการต่อจริง

ข้อจำกัดเหล่านี้ไม่มีอยู่ในเอกสารของ ธปท. และไม่มีทางรู้จากคำตอบที่ได้ ต้องเจอเองทีละข้อ
ทุกข้อถูกล็อกไว้ด้วยเทสต์แล้ว

| ข้อจำกัด | อาการเมื่อทำผิด |
|---|---|
| ช่วงวันที่กว้างเกินราว 1 เดือน | `400 Bad Request` โดย body บอกแค่ `"Bad Request"` |
| path ต้องมี `/` ปิดท้ายตามบรรทัด GET ในเอกสาร (Listen path ในหน้า Overview ตัดออก) | ตอบ 200 พร้อมแถวเปล่า เหมือนไม่มีข้อมูล |
| ชุดที่ไม่ได้ subscribe | `403 Access to this API has been disallowed` — เหมือนกับตอนคีย์ผิดทุกประการ |
| ธนาคารที่ไม่ประกาศอัตรา ส่ง `""` หรือ `0.0000` แล้วแต่ธนาคาร | ค่าเฉลี่ยเพี้ยนลงเงียบ ๆ ไม่มี error |
| ชุดอัตราดอกเบี้ยรวมสาขาธนาคารต่างประเทศมาด้วย | ค่าเฉลี่ยไม่ตรงกับที่ผู้กู้ไทยเจอจริง |
| `PolicyRate/v3` คืนค่าเดียวที่ `result.data` ไม่ใช่ `data_detail` | `no data_detail array` |
| "ไม่มีข้อมูล" มาได้สองแบบ: array ว่าง หรือแถวเดียวที่ทุกช่องว่าง | รายงานเป็นข้อผิดพลาดทั้งที่ไม่มีอะไรพัง |

### backend คุยกับ BOT อย่างไร

`botClient.ts` รับผิดชอบ:

| เรื่อง | วิธีจัดการ |
|---|---|
| Authentication | ส่ง key ผ่าน header `Authorization` เป็นโทเคนดิบ ไม่มี `Bearer` (ตั้งชื่อ header เองได้) ไม่เคยใส่ใน query string |
| Timeout | `AbortController` ตัดที่ `BOT_TIMEOUT_MS` |
| Retry | ถอยแบบทวีคูณ + สุ่มเล็กน้อย เฉพาะ 5xx / network / timeout เท่านั้น (401 ไม่ลองซ้ำ) |
| Rate limit | ถังโทเคนจำกัด `BOT_MAX_RPS`; เจอ 429 จะเคารพ `Retry-After` |
| ตรวจผลลัพธ์ | ต้องมีโครงสร้าง `result.data.data_detail` มิฉะนั้นโยน `BotApiError` |
| แปลงข้อมูล | รวมผลรายธนาคารเป็นค่าเฉลี่ยต่อวัน แปลงวันที่หลายรูปแบบเป็น `YYYY-MM-DD` |
| ปกป้องความลับ | ประกอบ error ใหม่โดยไม่พก header เดิม แล้วกรองด้วย `redactSecrets()` |

### แคชฝั่งเซิร์ฟเวอร์

สองชั้น: หน่วยความจำ → SQLite (`bot_series_cache`) แคชอยู่รอดข้ามการรีสตาร์ต และ
**แถวที่หมดอายุจะไม่ถูกลบทิ้ง** เพราะถ้า BOT ล่ม ระบบเลือกเสิร์ฟข้อมูลจริงที่เก่าหน่อย
(ติดป้าย `ข้อมูลค้าง`) ดีกว่าข้อมูลที่แต่งขึ้น ทุกจุดข้อมูลยังถูก upsert ลง `bot_observations`
ทำให้กราฟย้อนหลังใช้งานได้แม้เกตเวย์จะติดขัด

หน้าเว็บแสดง `Updated: …` และเวลาที่ดึงข้อมูลไว้ที่ป้ายที่มาของทุกการ์ด

### AI เข้าถึงข้อมูล BOT ผ่านเครื่องมือ/MCP อย่างไร

```
              ที่ปรึกษา AI                 โฮสต์ MCP ภายนอก
                   │                     (Claude Desktop / Claude Code)
                   │                              │ stdio JSON-RPC
                   │                              ▼
                   │                    apps/server/src/mcp/server.ts
                   │                     (ไม่ถือ credential ใด ๆ)
                   │                              │ POST /api/tools/:name/invoke
                   ▼                              ▼
        ┌────────────────────────────────────────────────┐
        │  ทะเบียนเครื่องมือ — นิยามที่เดียว ใช้ร่วมกันทุกทาง  │
        └────────────────────────────────────────────────┘
                   │
                   ▼
             botService → botClient → Bank of Thailand API
```

เครื่องมือ BOT ที่เปิดให้ AI เรียก:

```
get_bot_policy_rate()
get_bot_lending_rate(type)          // MLR | MOR | MRR | average
get_bot_deposit_rate(tenor)         // savings | 3m | 6m | 12m | 24m
get_bot_exchange_rate(currency)
get_bot_market_data()
get_bot_economic_indicator(indicator, start, end)
```

พร้อมเครื่องมือด้านการเงินและแหล่งเงินทุนอีก 14 ตัว (`analyze_financial_statement`,
`calculate_financial_ratios`, `calculate_loan_payment`, `estimate_financing_cost`,
`assess_debt_capacity`, `match_funding_programs`, …) รวมทั้งหมด **20 เครื่องมือ**
ดูรายการเต็มได้ที่ `GET /api/tools` หรือหน้า **เครื่องมือ / MCP** ในแอป

ตั้งค่าให้โฮสต์ MCP เชื่อมต่อ:

```json
{
  "mcpServers": {
    "sme-finance-copilot": {
      "command": "node",
      "args": ["apps/server/dist/mcp/server.js"],
      "env": { "MCP_API_BASE_URL": "http://localhost:8787" }
    }
  }
}
```

**กระบวนการ MCP ไม่ถือ API key** มันอ่านเฉพาะตัวแปรขึ้นต้นด้วย `MCP_` และส่งต่อทุกคำสั่ง
ไปยัง backend ผ่าน HTTP — มีเทสต์บังคับข้อนี้ไว้ (`apps/server/tests/mcp.test.ts`)

### ตัวอย่างการทำงานจริง

คำถาม: *"ตอนนี้ดอกเบี้ยสูงไหม และถ้าบริษัทกู้เงิน 10 ล้านบาทจะกระทบต้นทุนทางการเงินอย่างไร?"*

ที่ปรึกษาเรียกเครื่องมือตามลำดับ แล้วเรียบเรียงคำตอบจากผลที่ได้เท่านั้น
(ตัวเลขด้านล่างมาจากชุดข้อมูลจำลอง ใช้แสดงลำดับการเรียกเครื่องมือ ไม่ใช่ค่าปัจจุบัน):

```
1. get_bot_policy_rate            → 1.50%  (Bank of Thailand)
2. get_bot_lending_rate(average)  → 6.05%
3. analyze_financial_statement    → รายได้ ฿185,000,000 · EBIT ฿16,800,000
4. calculate_financial_ratios     → DSCR 1.43 เท่า · D/E 1.38 เท่า
5. estimate_financing_cost        → MRR 6.01% + 0.50% = 6.51% (ประมาณการ)
                                     ดอกเบี้ยปีแรก ฿599,424 · ค่างวด ฿195,708/เดือน
6. assess_debt_capacity           → DSCR 1.43 → 1.19 เท่า  ⚠️ รับได้แต่ตึง
```

คำตอบปิดท้ายด้วยหัวข้อ **ที่มาของข้อมูล** ที่ระบุแหล่งและวันที่ของทุกตัวเลข และตัวเลข
ที่คำนวณจากสมมติฐานถูกกำกับว่า **"ประมาณการ"** เสมอ

## ความสามารถหลัก

### 📊 ภาพรวมตลาด
ดึงราคาเหรียญมีมจาก CoinMarketCap (หรือข้อมูลจำลองถ้าไม่มี API key) เลือกได้จาก **26 เหรียญ** แบ่งเป็นหมวดสายหมา / สายแมว / สายกบ / สัตว์อื่น / คลาสสิก แสดงสภาพตลาดรวม
และ **แผนที่ความเสี่ยง–ผลตอบแทน** ที่วางทุกเหรียญเทียบกับเส้นเกณฑ์ CAPM —
จุดที่อยู่เหนือเส้นคือเหรียญที่ให้ผลตอบแทนคุ้มความเสี่ยงกว่าเพื่อนที่ระดับ β เดียวกัน

### 🧠 AI Financial Tools (วิเคราะห์รายเหรียญ)
- **ค่า Beta (β)** คำนวณจากข้อมูลจริงตามนิยาม `β = Cov(Ri, Rm) / Var(Rm)`
  พร้อมกราฟการถดถอยที่แสดงให้เห็นว่า β คือ "ความชัน" ของความสัมพันธ์กับตลาด
- **R², Alpha, Sharpe, Sortino, VaR 95%, CVaR, Max Drawdown** ครบชุด
- **พยากรณ์ราคา** ด้วย Monte Carlo (GBM) แสดงเป็นกราฟพัด พร้อมความน่าจะเป็นที่ราคาจะขึ้น
  และสถานการณ์ราคาที่ percentile 5 / 25 / 50 / 75 / 95
- **คำแนะนำ ซื้อ / ถือ / ขาย** จากการให้คะแนน 7 ปัจจัย พร้อม **กราฟอธิบายว่าปัจจัยไหน
  ดันคะแนนขึ้นหรือลงเท่าไหร่** — อธิบายได้ทุกการตัดสินใจ ไม่ใช่กล่องดำ

### 💎 ประเมินมูลค่า — ถือเท่านี้ ควรซื้อเพิ่มหรือขายออก
- **มูลค่าเหมาะสม (fair value)** คิดย้อนกลับจากราคาพยากรณ์ โดยคิดลดด้วยผลตอบแทนที่ความเสี่ยง
  เรียกร้องตาม CAPM — ราคาตลาดถูกหรือแพงกว่ามูลค่ากี่ %
- **บันไดราคา 5 โซน** บอกว่าที่ระดับราคาไหนควรทำอะไร (ซื้อเพิ่มหนัก / ทยอยซื้อ / ถือ /
  ทยอยขาย / ขายออก) โดยความกว้างของโซนแปรตามความผันผวนของเหรียญนั้น
- **ขนาดการถือครองด้วย Kelly Criterion** แบบเศษส่วน — คำนวณจากโอกาสขึ้นและอัตราได้/เสีย
  ที่ได้จาก Monte Carlo โดยตรง
- **รายการที่ทำตามได้ทันที**: เหรียญไหนควรซื้อเพิ่ม/ขายออกกี่ดอลลาร์ กี่เหรียญ
  พร้อมปุ่มสั่งให้พอร์ตจำลองทำตามแผนทั้งชุด

### 💼 บริหารพอร์ตด้วยค่า β
- **β ของพอร์ต** = `Σ (น้ำหนัก × β รายเหรียญ)` เทียบกับ β เป้าหมายที่ตั้งไว้
- **แยกให้เห็นว่าเหรียญไหนดัน β ของพอร์ตมากที่สุด** เพื่อตอบว่าถ้าจะลดความเสี่ยงควรตัดตัวไหนก่อน
- คะแนนการกระจายความเสี่ยง + เมทริกซ์สหสัมพันธ์ (เหรียญมีมมักลงพร้อมกัน — พอร์ตจึงกระจาย
  ความเสี่ยงได้น้อยกว่าที่คิด)
- **แผนปรับสมดุลพอร์ต** เทียบน้ำหนักปัจจุบันกับที่ AI แนะนำ ออกมาเป็นรายการซื้อ/ขายที่ทำตามได้เลย

### ⚡ บอทยิงออเดอร์อัตโนมัติ
ทำงานเป็นรอบ เรียงตามลำดับความสำคัญ:
1. **บริหารความเสี่ยงของสถานะเดิม** — ตัดขาดทุน (stop-loss) และทำกำไร (take-profit) อัตโนมัติ
   โดยระยะ stop ปรับตามความผันผวนของเหรียญนั้น
2. **ตรวจวงเงินขาดทุนของวัน** — ชนเพดานแล้วหยุดเปิดสถานะใหม่ (แต่ยังขายออกได้เสมอ)
3. **ทำตามสัญญาณ AI** — ทุกออเดอร์ต้องผ่าน **ด่านความเสี่ยง** ก่อน ได้แก่ ความมั่นใจขั้นต่ำ,
   เพดานน้ำหนักรายเหรียญ, จำนวนเหรียญสูงสุด, เงินสดสำรอง และ **เพดาน β ของพอร์ต**

ออเดอร์ที่ถูกปฏิเสธจะถูกบันทึกพร้อมเหตุผลเสมอ ทำให้ตรวจย้อนหลังได้ว่าทำไมบอทถึงไม่เข้าไม้นั้น
ราคาที่จับคู่รวม **ค่าธรรมเนียมและ slippage** แล้ว

## เบื้องหลังการคำนวณ

| แนวคิด | สูตร | ใช้ตอบคำถามอะไร |
|---|---|---|
| **Beta (β)** | `Cov(Ri, Rm) / Var(Rm)` | เหรียญนี้ผันผวนแรงกว่าตลาดกี่เท่า |
| **β ของพอร์ต** | `Σ wᵢ · βᵢ` | ทั้งพอร์ตเสี่ยงกว่าตลาดกี่เท่า เงินสดช่วยเจือจางได้เท่าไหร่ |
| **CAPM** | `E(Ri) = Rf + β(E(Rm) − Rf)` | ที่ความเสี่ยงระดับนี้ *ควรได้* ผลตอบแทนเท่าไหร่ถึงจะคุ้ม |
| **Jensen's Alpha** | `Ri − [Rf + β(Rm − Rf)]` | เหรียญนี้ทำได้ดีกว่าที่ความเสี่ยงควรให้หรือไม่ |
| **GBM (พยากรณ์)** | `S_T = S₀·exp((μ − σ²/2)T + σ√T·Z)` | ราคาในอนาคตมีโอกาสไปทางไหน กว้างแค่ไหน |
| **VaR / CVaR 95%** | percentile ที่ 5 ของผลตอบแทน | วันที่แย่ที่สุด 5% จะขาดทุนอย่างน้อยเท่าไหร่ |
| **มูลค่าเหมาะสม** | `E[P_T] / (1+r)^T` | วันนี้เหรียญนี้ควรมีมูลค่าเท่าไหร่ |
| **Kelly Criterion** | `f* = (p·b − q) / b` | ควรถือเป็นสัดส่วนเท่าไหร่ของพอร์ต |
| **คะแนนกระแส** | `0.4·ปริมาณ + 0.4·การเร่งตัว + 0.2·อารมณ์` | ตอนนี้เหรียญไหนกำลังเป็นกระแส |

**ค่า drift (μ) ที่ใช้พยากรณ์ไม่ได้เดาลอย ๆ** แต่ผสมจาก 3 แหล่ง: ผลตอบแทนที่ควรได้ตาม CAPM (45%),
โมเมนตัมที่เกิดขึ้นจริง (35%) และแรงกลับสู่ค่าเฉลี่ยเมื่อราคาหลุดจาก SMA ไปมาก (20%)

**คะแนน AI** มาจาก 7 ปัจจัยถ่วงน้ำหนัก (รวมกันได้ 1.00):

| ปัจจัย | น้ำหนัก | ปัจจัย | น้ำหนัก |
|---|---|---|---|
| ผลตอบแทนเทียบเกณฑ์ CAPM | 22% | แนวโน้ม (SMA30 + MACD) | 15% |
| พยากรณ์ Monte Carlo | 18% | RSI / การกลับสู่ค่าเฉลี่ย | 10% |
| โมเมนตัมราคา | 20% | โทษความเสี่ยง (β/ผันผวน/drawdown) | 10% |
| | | สภาพคล่อง | 5% |

ครอบคลุม 341 รายการ รวมถึงจุดที่พลาดง่ายและมีผลต่อความถูกต้องของระบบ:

- **β ต้องคำนวณถูก** — สินทรัพย์ที่ขยับเหมือนตลาดต้องได้ β = 1, ขยับสองเท่าต้องได้ 2,
  สวนทางต้องติดลบ และต้องคืนค่า β ที่ตั้งใจไว้ได้จากข้อมูลที่มี noise
- **ไม่มี look-ahead bias** — คะแนนสัญญาณ ณ วันที่ t ต้องไม่เปลี่ยน แม้จะแก้ราคาในอนาคต
- **Monte Carlo ต้องตรงกับสูตรปิด** — ความน่าจะเป็นขาขึ้นจากการจำลองต้องตรงกับ
  `Φ((μ−σ²/2)T / σ√T)` ภายใน ±2%
- **ด่านความเสี่ยงต้องปิดกั้นได้จริง** — ทุกด่าน (β, น้ำหนัก, เงินสด, ความมั่นใจ, วงเงินขาดทุน)
  มีเทสต์แยกของตัวเอง รวมถึงเทสต์ว่าการชนวงเงินขาดทุน **ต้องยังขายออกได้**
- **หน้าเว็บรันได้จริง** — ใช้ `AppTest` ของ Streamlit กดปุ่ม เปลี่ยนค่า และสลับเหรียญจริง
  เพื่อจับ error ที่เกิดเฉพาะตอนเรนเดอร์
- **ไม่ลงโทษความผันผวนซ้ำสองครั้ง** — มูลค่าเหมาะสมต้องอิงค่าคาดหวัง ไม่ใช่ค่ากลาง
  เพราะค่ากลางของ lognormal มีตัวหน่วง −σ²/2 ติดมาแล้ว มีเทสต์ล็อกพฤติกรรมนี้ไว้
- **การปรับสเกลตามงบลงทุน** — Kelly กำหนดสัดส่วนเปรียบเทียบ ส่วนงบลงทุนกำหนดระดับ
  ความเสี่ยงรวม เทสต์ครอบคลุมทั้งการคงลำดับ การชนเพดาน และการคืนส่วนเกินให้ตัวอื่น
- **แชตบอทต้องไม่แต่งตัวเลข** — มีเทสต์ยืนยันว่าคำตอบอ้างค่า β ราคา และสัญญาณจริง
  จากระบบ และต้องบอกผู้ใช้เมื่อกระแสโซเชียลเป็นข้อมูลจำลอง
- **แหล่งข้อมูลภายนอกล่มต้องไม่ทำให้เว็บพัง** — timeout สั้นมากในเทสต์เพื่อบังคับให้
  เส้นทาง fallback ทำงานจริง

## หมายเหตุด้านการออกแบบกราฟ

- **ไม่ใช้แกน y สองแกน** ในกราฟเดียว — เมื่อต้องเทียบของที่หน่วยต่างกัน จะปรับเป็นฐาน 100 แทน
- สีถูกเลือกและตรวจสอบกับพื้นหลังมืดโดยเฉพาะ ผ่านเกณฑ์การแยกแยะสำหรับผู้ที่มีภาวะตาบอดสี
- สัญญาณ ซื้อ/ถือ/ขาย แยกด้วย **ทั้งสีและรูปทรงหมุด** เพราะคู่สีแดง-เทาแยกยากสำหรับผู้ที่
  ตาบอดสีแบบ protan — รูปทรงจึงเป็นช่องทางสำรอง
- ทุกกราฟมี tooltip และมี legend เมื่อมีตั้งแต่ 2 ชุดข้อมูลขึ้นไป
