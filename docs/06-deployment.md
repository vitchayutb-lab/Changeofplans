# 6. การนำขึ้นเว็บจริง (Deployment)

เอกสารนี้อธิบายวิธีนำ **SME Finance Copilot** ขึ้นเว็บให้เข้าถึงได้จากอินเทอร์เน็ต
ไม่ใช่แค่รันบนเครื่องตัวเอง

---

## 6.1 ข้อจำกัดที่กำหนดตัวเลือก

**แอปนี้ต้องรันบนเซิร์ฟเวอร์ Node จริง ใช้ static hosting ไม่ได้**

เหตุผลอยู่ที่กฎ R3 ในเอกสารสถาปัตยกรรม: `BOT_API_KEY` ต้องไม่หลุดออกไปที่เบราว์เซอร์
ถ้าเอาแต่ไฟล์หน้าเว็บไปวางบน static host (GitHub Pages, Netlify แบบ static, S3)
จะไม่มีที่ให้เก็บคีย์และไม่มีตัวกลางเรียก BOT API ให้

| แพลตฟอร์ม | ใช้ได้ไหม | เหตุผล |
|---|---|---|
| Render / Railway / Fly.io / Cloud Run / VPS | ✅ | รันโปรเซส Node ได้ตลอดเวลา เก็บ secret ฝั่งเซิร์ฟเวอร์ได้ |
| GitHub Pages, Netlify (static), S3 + CloudFront | ❌ | ไม่มีฝั่งเซิร์ฟเวอร์ให้เก็บคีย์และเรียก BOT API |
| Vercel / Netlify Functions | ⚠️ | รันได้ แต่ระบบไฟล์ชั่วคราว SQLite จะรีเซ็ตบ่อยและแคชไม่อยู่ข้ามคำขอ |

สิ่งที่ต้องมี:

- **Node 20 ขึ้นไป** (image ใช้ Node 22)
- **ดิสก์ถาวร** ถ้าต้องการให้ประวัติแชตและแคช BOT อยู่ข้ามการ deploy
  (ไม่มีก็รันได้ ระบบจะใส่ข้อมูลตั้งต้นให้ใหม่ทุกครั้ง)
- **พอร์ตจาก `PORT`** และผูกกับ `0.0.0.0` (image ตั้งให้แล้ว)

---

## 6.2 ทางเลือกที่ 1 — Render (ง่ายที่สุด มีแผนฟรี)

ที่เก็บโค้ดมี [`render.yaml`](../render.yaml) อยู่แล้ว Render จะอ่านเองทั้งหมด

1. ไปที่ [dashboard.render.com](https://dashboard.render.com) → **New** → **Blueprint**
2. เลือก repo นี้ แล้วกด **Apply** — Render จะ build จาก `Dockerfile` ให้เอง
3. รอ build เสร็จ (~5 นาทีครั้งแรก) จะได้ URL หน้าตา
   `https://sme-finance-copilot.onrender.com`
4. เปิด URL — แอปจะขึ้นมาใน **DEMO MODE** ทันทีโดยยังไม่ต้องตั้งค่าอะไร

### เปิดใช้ข้อมูลจริงจาก ธปท.

ไปที่ **Environment** ของบริการ แล้วเพิ่ม:

| Key | Value |
|---|---|
| `BOT_API_KEY` | Client ID ที่ได้จาก BOT API Portal |
| `ANTHROPIC_API_KEY` | *(ไม่บังคับ)* ให้ Claude เรียบเรียงคำตอบ |

กด **Save** แล้ว Render จะ deploy ใหม่ให้เอง จากนั้นเช็คที่หน้า **เครื่องมือ / MCP**
ว่าช่อง "ตั้งค่า API key แล้ว" ขึ้นว่า *ใช่* และ "สำเร็จล่าสุด" มีเวลาแสดง

> ทั้งสองค่าตั้งเป็น `sync: false` ใน `render.yaml` แปลว่า Render จะไม่ดึงค่าจากไฟล์
> ต้องกรอกในหน้าเว็บเท่านั้น — ค่าจึงไม่มีทางถูก commit ลง Git

### ข้อควรรู้ของแผนฟรี

- เครื่องจะ **พักเมื่อไม่มีคนเข้า 15 นาที** คำขอแรกหลังพักจะช้าราว 30–50 วินาที
- **ไม่มีดิสก์ถาวร** ฐานข้อมูลรีเซ็ตทุกครั้งที่ deploy ใหม่ (ข้อมูลตั้งต้นจะถูกใส่ให้เอง
  แต่ประวัติแชตและแคช BOT จะหาย)

อยากให้ข้อมูลอยู่ถาวร: เปลี่ยน `plan: free` เป็น `plan: starter` ใน `render.yaml`
เปิดบล็อก `disk:` ที่คอมเมนต์ไว้ แล้วเปลี่ยน `SQLITE_PATH` เป็น `/data/app.db`

## 6.3 ทางเลือกที่ 2 — Fly.io (มีดิสก์ถาวรราคาถูก)

ที่เก็บโค้ดมี [`fly.toml`](../fly.toml) อยู่แล้ว

```bash
fly launch --no-deploy --copy-config    # สร้างแอปจากไฟล์ fly.toml
fly volumes create data --size 1        # ดิสก์ถาวร 1GB สำหรับ SQLite
fly secrets set BOT_API_KEY=xxxxx       # ไม่ใส่ก็รันใน DEMO MODE ได้
fly deploy
fly open                                # เปิดเว็บที่ deploy แล้ว
```

`fly.toml` ตั้ง `auto_stop_machines` ไว้ เครื่องจะหยุดเองเมื่อไม่มีคนใช้และปลุกกลับมา
เมื่อมีคนเข้า ทำให้ค่าใช้จ่ายต่ำ

> **สำคัญ:** SQLite เขียนไฟล์เดียว อย่าสเกลเกินหนึ่ง instance ที่เขียนได้
> ถ้าต้องการหลาย instance ให้เปลี่ยนไปใช้ Postgres ก่อน

## 6.4 ทางเลือกที่ 3 — Docker ที่ไหนก็ได้ (VPS, Cloud Run, Azure)

```bash
docker build -t sme-finance-copilot .

docker run -d \
  --name sme-finance-copilot \
  -p 80:8787 \
  -e BOT_API_KEY=xxxxx \
  -v sme-data:/data \
  --restart unless-stopped \
  sme-finance-copilot
```

image จัดการให้แล้ว: build แบบหลายขั้นเพื่อไม่เอาซอร์สและ devDependency ติดไปด้วย
รันด้วยผู้ใช้ที่ไม่ใช่ root มี `HEALTHCHECK` ในตัว และตั้ง `SQLITE_PATH=/data/app.db`
ให้ผูก volume ได้เลย

**หลัง reverse proxy (nginx / Caddy / Cloudflare)** ให้ตั้ง `TRUST_PROXY` เท่ากับจำนวนชั้น
ของ proxy ที่อยู่หน้า มิฉะนั้นตัวจำกัดอัตราคำขอจะเห็นทุกคนเป็น IP เดียวกัน

## 6.5 ตัวแปรสภาพแวดล้อมตอน deploy

ค่าที่ต้องสนใจเป็นพิเศษเมื่อขึ้นเว็บจริง (รายการเต็มอยู่ใน README):

| ตัวแปร | ค่าเริ่มต้น | ทำไมสำคัญตอน deploy |
|---|---|---|
| `NODE_ENV` | `development` | ต้องเป็น `production` — ตัวนี้เปิดการเสิร์ฟหน้าเว็บและปิด CORS |
| `HOST` | `0.0.0.0` | ต้องเป็น `0.0.0.0` ในคอนเทนเนอร์ ไม่งั้น load balancer ต่อไม่ติดและ deploy จะค้าง |
| `PORT` | `8787` | แพลตฟอร์มส่วนใหญ่กำหนดค่านี้ให้เอง — อย่าฮาร์ดโค้ดทับ |
| `SQLITE_PATH` | `apps/server/data/app.db` | ชี้ไปยัง volume เช่น `/data/app.db` ถ้าต้องการให้ข้อมูลอยู่ถาวร |
| `TRUST_PROXY` | `1` ตอน production | จำนวนชั้นของ reverse proxy ที่อยู่หน้า มีผลต่อการนับ IP ของตัวจำกัดอัตรา |
| `CORS_ORIGIN` | *(ว่างตอน production)* | ปล่อยว่างไว้เมื่อหน้าเว็บอยู่โดเมนเดียวกัน ตั้งค่าเฉพาะเมื่อแยกโดเมน |
| `RATE_LIMIT_MAX` | `240` | คำขอต่อ IP ต่อนาทีสำหรับ `/api` ทั้งหมด |
| `RATE_LIMIT_EXPENSIVE_MAX` | `20` | เพดานแยกของ `/api/advisor/chat` และ `/api/tools` |
| `WEB_DIST_PATH` | *(หาให้อัตโนมัติ)* | ตั้งเมื่อวางไฟล์หน้าเว็บไว้คนละที่กับ layout ของ repo |
| `BOT_API_BASE_URL` | `https://apigw1.bot.or.th/bot/public` | ต้องเป็น URL เต็มที่มี `https://` — ถ้าผิดระบบจะเตือนตอนบูตและแสดงข้อมูลจำลองแทน |
| `BOT_API_KEY_HEADER` | `X-IBM-Client-Id` | ชื่อ header ที่ใช้ส่งคีย์ ปรับได้ถ้าเอกสารของ BOT ระบุชื่ออื่น |

## 6.6 ทำไมต้องมีตัวจำกัดอัตราคำขอ

พอเปิดเป็น URL สาธารณะ ใครก็ยิงเข้ามาได้ สองเส้นทางนี้แพงกว่าเส้นทางอื่นมาก:

- `POST /api/advisor/chat` — เรียกเครื่องมือหลายตัวต่อหนึ่งคำถาม และถ้าตั้ง
  `ANTHROPIC_API_KEY` ไว้ก็จะเรียก Claude ด้วย นั่นคือเงินจริงของเจ้าของแอป
- `POST /api/tools/:name/invoke` — เรียกเครื่องมือได้โดยตรง รวมถึงเครื่องมือที่ไปแตะ BOT API

ระบบจึงจำกัดสองเส้นทางนี้ไว้เข้มกว่าปกติ (`RATE_LIMIT_EXPENSIVE_MAX`) และจำกัด
`/api` ทั้งหมดอีกชั้น ผู้ที่ถูกจำกัดจะได้ HTTP 429 พร้อม `Retry-After`

ตัวนับเก็บในหน่วยความจำของ process เดียว เพียงพอสำหรับการ deploy ขนาดเล็ก
ถ้าขยายเป็นหลาย instance ต้องเปลี่ยนไปใช้ตัวนับส่วนกลาง (เช่น Redis)

## 6.7 เช็กลิสต์หลัง deploy

1. **`GET /api/health`** ตอบ `status: "ok"` และ `modes.database: "ok"`
2. เปิดหน้าแรก — การ์ดทั้งสี่ใบขึ้นตัวเลข และมีป้ายที่มาใต้ทุกใบ
3. กดเข้าหน้า **เครื่องมือ / MCP** แล้วดู:
   - `ตั้งค่า API key แล้ว` — บอกว่าใส่คีย์ BOT ไปหรือยัง
   - `สำเร็จล่าสุด` / `ผิดพลาดล่าสุด` — บอกว่าเรียก BOT API ได้จริงไหม
4. ถ้าใส่คีย์แล้วแต่ยังขึ้น `Demo Data` ให้ดูข้อความใน `ผิดพลาดล่าสุด`:
   - **`ตั้งค่า BOT_API_BASE_URL ไม่ถูกต้อง`** → ตัวแปรนี้ผิด ไม่ใช่ตัว API key
     ต้องเป็น URL เต็มที่ขึ้นต้นด้วย `https://` ไม่ใช่แค่ชื่อโฮสต์
     ระบบจะเตือนเรื่องนี้ตั้งแต่ตอนเซิร์ฟเวอร์เริ่มทำงานด้วย และหน้า **เครื่องมือ / MCP**
     จะขึ้นแบนเนอร์แดงบอกวิธีแก้
   - `HTTP 401/403` → คีย์ผิด หรือยังไม่ได้สมัครใช้ชุดข้อมูลนั้น
     (BOT ให้สมัครแยกรายชุด คีย์เดียวไม่ได้เปิดทุกชุดอัตโนมัติ)
   - `timed out` → เพิ่ม `BOT_TIMEOUT_MS`
   - `contained no readable values` → เรียกติดแล้ว แต่ชื่อคอลัมน์ในผลลัพธ์ต่างจากที่ระบบคาด
     ปรับ `valueFields` ใน [`botSeries.ts`](../apps/server/src/services/bot/botSeries.ts)
5. ลองถามที่ปรึกษา AI หนึ่งคำถาม แล้วกดดู "เครื่องมือที่เรียกใช้" ว่ามี trace ครบ

## 6.8 สิ่งที่ควรทำเพิ่มก่อนใช้งานจริงกับข้อมูลลูกค้า

โครงนี้ทำมาเพื่อสาธิตและใช้ภายใน ถ้าจะให้ SME ภายนอกใช้จริงควรเพิ่ม:

- **ระบบยืนยันตัวตนและการแบ่งสิทธิ์** ตอนนี้ใครเปิด URL ได้ก็เห็นข้อมูลทุกกิจการ
- **เปลี่ยนจาก SQLite เป็น Postgres** เมื่อต้องรองรับหลาย instance หรือข้อมูลจริง
- **สำรองข้อมูล** ของ volume ที่เก็บฐานข้อมูล
- **บันทึก log และ error tracking** ที่ดูย้อนหลังได้
- **ตรวจสอบเงื่อนไขการใช้ข้อมูลของ ธปท.** ก่อนเผยแพร่ข้อมูลต่อสาธารณะ
